VISLite 贡献指南 VISLite Contribution Guide

环境搭建 Environment Setup

  • 需要安装 Node.js 。 Need to install Node.js.
  • 克隆仓库到本地后，执行 npm install 安装开发依赖。 After cloning the repository locally, run npm install to install development dependencies.
  • 安装EditorConfig插件来规范编辑器。 Install the EditorConfig plugin to standardize the editor.

开发 Development

直接执行 npm run dev 即可启动开发环境。 Run npm run dev to start the development environment.

  • 如果是编辑文档，访问： http://127.0.0.1:20000/docs/index.html 。 If editing documentation, visit: http://127.0.0.1:20000/docs/index.html.
  • 如果是调试功能，访问： http://127.0.0.1:20000/test/example 后选择对应的用例即可。 If debugging features, visit: http://127.0.0.1:20000/test/example and select the corresponding test case.

新增调试页面，只需要在test项目中新建即可，比如： To add a new debug page, simply create it in the test project, for example: 

- test
    - example
        - newApi
            - index.html
            - index.ts

新增功能 Add New Feature

主体代码写在 src 目录中，按照功能分类，对外暴露则在 package 目录中，结构如下： The main code is written in the src directory, categorized by functionality. Exposed APIs are placed in the package directory with the following structure: 

- package
    - newApi
        - index.ts

此外，还需要在 package/index.ts 中进行注册。 Additionally, you need to register it in package/index.ts.

接着，在 types/index.d.ts 中定义类型，大体格式如下： Then, define types in types/index.d.ts, roughly as follows: 

export default class VISLite {
    static newApi: newApiType
}

export let newApi: newApiType

比如，上面的具体类型 newApiType 或相关参数的类型可以在 types 中独立定义，方便项目中引入。 For example, the specific type newApiType or related parameter types can be defined independently in types for easy import in the project.

一切完毕后，最后在 docs 中添加文档，并在 CHANGELOG 中登记就完成了所有内容。 After everything is done, add documentation in docs and record it in CHANGELOG to complete all tasks.

测试 Testing

除了开发时候的调试外，还需要添加如下测试： In addition to debugging during development, the following tests need to be added:

  • （可选）基准测试：在 test/benchmark/index.ts 中添加。 (Optional) Benchmark test: Add in test/benchmark/index.ts.
  • （可选）单元测试：直接新建文件 test/unit/newApi.spec.ts 即可。 (Optional) Unit test: Create a new file test/unit/newApi.spec.ts.
  • （必选）ESLint：直接运行 npm run lint 并保证没有报错。 (Required) ESLint: Run npm run lint and ensure no errors.

除了调试的测试文件和必选项外，上述测试都根据实际情况添加即可。 Except for debugging test files and required items, the above tests can be added according to actual needs.

提交 PR Submit PR

  • fork 本仓库，在自己仓库基于 dev 分支创建专用分支用于提交更改。 Fork this repository and create a dedicated branch based on the dev branch in your own repository for submitting changes.
  • commit 内容请说明清楚本次 PR 的主要目的和改动，描述清楚即可。 The commit message should clearly describe the main purpose and changes of this PR.
  • 提交之前尽力确保进行了完整的测试。 Make sure to run complete tests before submitting.
  • 确保 PR 提交到 dev 分支。 Ensure the PR is submitted to the dev branch.
  • 修复 Bug 请提供详细的描述信息，或链接到对应的 issue。 When fixing a bug, provide detailed description or link to the corresponding issue.
